# C4 Diagram Instructions

Use this when creating architecture diagrams at any of the three C4 levels.

## C4 Levels

| Level | Diagram | Shows | File naming |
|-------|---------|-------|-------------|
| L1 | System Context | Actors, the system, external systems | `c4-level1-context.pu` |
| L2 | Container | Deployable units, databases, external services | `c4-level2-containers.pu` |
| L3 | Component | Internal components of one container | `c4-level3-{app}-components.pu` |

If the user asks for "architecture" without specifying a level, generate L1 + L2 together in the same file.

## C4-PlantUML Stdlib Includes

```plantuml
' L1 — System Context
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml

' L2 — Container
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml

' L3 — Component
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml
```

Each include provides the macros for its level. You only need to include the one matching the diagram level.

**Do not add `!theme plain` or any `skinparam` blocks** — the C4-PlantUML stdlib ships its own styles; overriding them breaks the C4 visual identity.

## C4 Element Macros

### People / Actors
```plantuml
Person(alias, "Label", "Description")
Person_Ext(alias, "Label", "Description")   ' external person (greyed)
```

### Systems
```plantuml
System(alias, "Label", "Description")
System_Ext(alias, "Label", "Description")   ' external system (greyed)
SystemDb(alias, "Label", "Description")     ' database system
SystemDb_Ext(alias, "Label", "Description")
```

### Containers (L2 only)
```plantuml
Container(alias, "Label", "Technology", "Description")
ContainerDb(alias, "Label", "Technology", "Description")
Container_Ext(alias, "Label", "Technology", "Description")
```

### Components (L3 only)
```plantuml
Component(alias, "Label", "Technology", "Description")
ComponentDb(alias, "Label", "Technology", "Description")
```

## Relationship Macros

```plantuml
Rel(from, to, "Label")
Rel(from, to, "Label", "Technology")   ' with protocol/tech
BiRel(a, b, "Label")                    ' bidirectional
Rel_D(from, to, "Label")               ' forced direction: Down
Rel_U(from, to, "Label")               ' Up
Rel_L(from, to, "Label")               ' Left
Rel_R(from, to, "Label")               ' Right
```

## L1 — System Context Template

```plantuml
@startuml c4-level1-context
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Context.puml

title <System Name> — System Context

Person(user, "End User", "Uses the system via web or mobile")
Person_Ext(admin, "Administrator", "Manages configuration")

System(system, "<System Name>", "Core application")

System_Ext(auth, "Auth Provider", "OAuth / SSO")
System_Ext(email, "Email Service", "Transactional emails")
SystemDb_Ext(erp, "ERP", "External business data")

Rel(user, system, "Uses")
Rel(admin, system, "Configures")
Rel(system, auth, "Authenticates via")
Rel(system, email, "Sends emails via")
Rel(system, erp, "Reads data from")

@enduml
```

## L2 — Container Template

```plantuml
@startuml c4-level2-containers
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Container.puml

title <System Name> — Container Diagram

Person(user, "End User", "")

System_Boundary(sys, "<System Name>") {
  Container(web, "Web App", "Next.js", "SPA served to browser")
  Container(api, "API", "Node.js / Express", "REST API")
  ContainerDb(db, "Database", "PostgreSQL", "Stores domain data")
  Container(queue, "Queue", "Redis", "Async job processing")
  Container(worker, "Worker", "Node.js", "Processes background jobs")
}

System_Ext(auth, "Auth Provider", "OAuth / SSO")
System_Ext(email, "Email Service", "SMTP / SaaS")

Rel(user, web, "Uses", "HTTPS")
Rel(web, api, "Calls", "HTTPS/JSON")
Rel(api, db, "Reads/Writes", "SQL")
Rel(api, queue, "Enqueues jobs", "Redis protocol")
Rel(worker, queue, "Dequeues jobs", "Redis protocol")
Rel(worker, db, "Reads/Writes", "SQL")
Rel(api, auth, "Validates tokens", "HTTPS")
Rel(worker, email, "Sends emails", "HTTPS")

@enduml
```

## L3 — Component Template

```plantuml
@startuml c4-level3-api-components
!include https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_Component.puml

title <System Name> — <App> Components

Container_Boundary(api, "<App>") {
  Component(router, "Router", "Express", "Routes incoming HTTP requests")
  Component(controller, "Controllers", "Express handlers", "Handle request/response lifecycle")
  Component(service, "Domain Services", "TypeScript", "Business logic")
  Component(repo, "Repositories", "TypeScript", "Data access layer")
  Component(auth_mid, "Auth Middleware", "JWT", "Validates bearer tokens")
}

ContainerDb_Ext(db, "Database", "PostgreSQL", "")
System_Ext(auth, "Auth Provider", "")

Rel(router, auth_mid, "Routes through")
Rel(auth_mid, controller, "Passes to")
Rel(controller, service, "Calls")
Rel(service, repo, "Uses")
Rel(repo, db, "Queries", "SQL")
Rel(auth_mid, auth, "Validates token", "HTTPS")

@enduml
```

## Step-by-Step Process

1. **Determine level** — L1 (whole system), L2 (containers), L3 (one container's internals)
2. **Choose the right include** — one `!include` per diagram
3. **Identify people** — who interacts with the system?
4. **Identify external systems** — what does it integrate with? Use `_Ext` variants
5. **Add relationships** — use directional helpers (`Rel_D`, `Rel_L`) to avoid crossing arrows

## Best Practices

- Use `_Ext` variants for everything outside the system boundary — they render greyed out
- Keep L1 to 5-8 elements maximum
- Keep L2 to one `System_Boundary` block — containers inside, external systems outside
- L3 diagrams are per-container — create a separate `.pu` file per app, not one giant diagram
- Use `Rel` technology parameter to show protocol (HTTPS, SQL, gRPC, etc.)
- **Never add `!theme plain` or `LAYOUT_WITH_LEGEND()`** — the stdlib handles its own visual style

## When to Use Each Level

- **L1** — communicating scope to non-technical stakeholders
- **L2** — communicating deployment topology and integration points
- **L3** — communicating internal design of one service to developers

## Dependencies

| Library | Source | Pin status |
|---------|--------|------------|
| C4-PlantUML stdlib | `https://raw.githubusercontent.com/plantuml-stdlib/C4-PlantUML/master/C4_*.puml` | ⚠️ unpinned — pulls `master` at render time |
| PlantUML jar | `/tmp/plantuml.jar` — pinned to `1.2026.1` (see SKILL.md validation section) | ✓ pinned |

> The C4 stdlib `!include` is a runtime HTTP fetch. If `master` introduces breaking changes, diagrams will fail silently. To pin, replace `master` with a specific commit SHA or release tag from https://github.com/plantuml-stdlib/C4-PlantUML/releases.
